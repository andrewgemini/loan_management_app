ภาพ `/admin` และ `/profile` ที่ถ่ายเดสก์ท็อปครั้งแรกอยู่ในสถานะ loading skeleton ของ DashboardLayout จึงต้องถ่ายซ้ำหลัง state การยืนยันตัวตนและ query เสร็จสมบูรณ์ การตรวจโค้ด TypeScript และ Vitest จะทำควบคู่กับการตรวจภาพ เพื่อแยกปัญหาจาก loading state ออกจากปัญหา layout จริง

ภาพมือถือที่ `/`, `/admin` และ `/profile` แสดงผลครบ โดยหน้าเริ่มต้นเรียง Hero และการ์ดข้อมูลเป็นคอลัมน์เดียว, หน้า Admin แสดง Activity History, ตัวเลขสรุป, tab และกราฟในความกว้างหน้าจออย่างไม่มี overflow, และหน้า Profile แสดง fallback initials กับปุ่มเปลี่ยนรูปโปรไฟล์อย่างอ่านง่าย การยืนยัน Avatar หลังอัปโหลดจริงจะครอบคลุมผ่าน router test ที่ mock storage และการบันทึก URL ระดับบัญชี

รอบล่าสุดตรวจเดสก์ท็อปที่ `/admin/activity-history` และ `/profile` แล้ว หน้า Activity History แสดง navigation สำหรับ Admin, input วันเริ่มต้น/วันสิ้นสุด, preset และ empty state โดยไม่มีข้อมูลสร้างขึ้นมาเพื่อการสาธิต ขณะที่หน้า Profile แสดง fallback initial เมื่อไม่มี Avatar ซึ่งสอดคล้องกับพฤติกรรมหลังลบรูป ผู้ใช้ที่มีรูปบันทึกอยู่จะเห็นปุ่มลบรูปและ dialog ยืนยันตามการทดสอบ render

หน้าจอมือถือของทั้งสองหน้าเรียงตัวกรองช่วงวันที่และ preset เป็นแนวตั้ง อ่านป้ายกำกับและปุ่มล้างตัวกรองได้ครบ โดยไม่มี overflow ในภาพที่ตรวจ ขณะเดียวกัน Profile คง fallback initial และปุ่มอัปโหลดตามพื้นที่จอขนาดเล็กอย่างเหมาะสม

รอบล่าสุดหน้า Activity History บนเดสก์ท็อปแสดงตัวกรองวันเริ่มต้น/สิ้นสุด ประเภทเหตุการณ์ และผู้ดำเนินการครบ พร้อมปุ่ม CSV/PDF ที่ปิดใช้งานเมื่อยังไม่มีผลลัพธ์ การ capture พบ skeleton loading ตามการออกแบบก่อนข้อมูล query กลับมา ขณะที่ Profile fallback state ยังแสดงผลสมบูรณ์

การตรวจบนมือถือยืนยันว่าตัวกรองทั้งสี่ส่วน ปุ่มล้างตัวกรอง และปุ่ม CSV/PDF เรียงเป็นลำดับเดียว อ่านและกดใช้งานได้ภายในความกว้างจอ โดย empty state ไม่ทำให้เกิด overflow

รอบล่าสุดบนเดสก์ท็อป หน้า Activity History แสดง Card กิจกรรมรายวันไว้ส่วนบน พร้อม empty state ที่สื่อความหมายเมื่อยังไม่มีข้อมูลจริง ตัวกรองบทบาทผู้ดำเนินการและพื้นที่บันทึก/เลือก/ลบชุดตัวกรอง browser-local อยู่ในแผงเดียวกันโดยไม่ทำให้ layout ล้น

การตรวจบนมือถือยืนยันว่า Card กิจกรรมรายวัน ตัวกรองวัน/เหตุการณ์/ผู้ดำเนินการ/บทบาท และส่วนชุดตัวกรองที่บันทึกไว้เรียงแนวตั้งโดยอ่านง่าย ปุ่ม CSV/PDF และปุ่มบันทึกยังอยู่ในพื้นที่กดที่เหมาะสม ไม่มี horizontal overflow ในภาพที่ตรวจ

รอบล่าสุดบนเดสก์ท็อป หน้า Activity History แสดงข้อความนำทางให้คลิกกราฟรายวันเพื่อดูรายละเอียดของวันนั้น, เพิ่มตัวเลือกผู้ให้กู้จากข้อมูลสัญญา และเปลี่ยนพื้นที่ชุดตัวกรองเป็น "ชุดตัวกรองของบัญชี" เพื่อสื่อการใช้งานข้ามอุปกรณ์ได้ชัดเจน กรณีไม่มีข้อมูลกิจกรรมจริงจะแสดง empty state ของกราฟและตารางโดยไม่ทำให้โครงหน้าจอเสีย
