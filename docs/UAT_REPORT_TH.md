# รายงาน UAT ระบบจัดการเงินกู้

เอกสารนี้บันทึกการตรวจสอบระบบในสภาพแวดล้อมพัฒนา ณ วันที่ 27 สิงหาคม 2569 โดยใช้ชุด regression tests, การตรวจ TypeScript, production build และ visual smoke test ของเส้นทางหลัก ไม่ได้เพิ่มข้อมูลจำลองหรือเปลี่ยนข้อมูลธุรกิจในฐานข้อมูลจริง ผลที่ผ่านจึงยืนยันความถูกต้องของสัญญาโปรแกรม การควบคุมสิทธิ์ และการแสดงผลในระดับเทคนิค ส่วนการรับรองกระบวนการธุรกิจปลายทางยังต้องทำร่วมกับผู้ใช้ที่มีบัญชีและสัญญาจริงในระบบ UAT

> **ผลสรุป:** ผ่านการตรวจสอบเชิงเทคนิค โดย regression tests ผ่าน **58 ไฟล์ / 170 tests**, TypeScript ผ่าน และ production build สำเร็จ ไม่มี runtime error ที่พบจาก visual smoke test ของเส้นทางที่ตรวจสอบ

## ขอบเขตและวิธีทดสอบ

การทดสอบครอบคลุมเส้นทางหลักตามบทบาท Borrower, Lender และ Admin รวมทั้งการคำนวณตารางผ่อน การชำระเงิน การตั้งค่าการแจ้งเตือน การส่งออกข้อมูล ประวัติกิจกรรม Audit/Governance และ Dashboard Presets/Folder ระดับการยอมรับของผู้ใช้แบ่งเป็นสองส่วน ได้แก่ การยืนยันอัตโนมัติที่ทำซ้ำได้ และการตรวจด้วยสายตาใน viewport เดสก์ท็อปและมือถือ

| รหัส | วิธีตรวจสอบ | หลักฐาน | ผล |
|---|---|---|---|
| TECH-01 | ตรวจชนิดข้อมูล | `pnpm check` | ผ่าน |
| TECH-02 | Regression suite | `pnpm test -- --run` | ผ่าน 58 ไฟล์ / 170 tests |
| TECH-03 | Production build | `pnpm build` | ผ่าน; มีคำเตือน bundle ใหญ่เดิมที่ไม่ขัดขวาง build |
| VIS-01 | Visual smoke desktop | 12 เส้นทางหลัก | ผ่าน; ตรวจ layout, skeleton, error/access states |
| VIS-02 | Visual smoke mobile | Dashboard, สร้างคำขอกู้, ตั้งค่าการแจ้งเตือน, Activity History, Governance และ Admin | ผ่าน; layout responsive และ state ตามสิทธิ์แสดงชัดเจน |
| LOG-01 | Runtime diagnostics | dev server และ browser diagnostics ที่พร้อมใช้งาน | ไม่พบ error ระหว่าง QA |

## ผล UAT ตามบทบาท

| บทบาท | สถานการณ์ที่ตรวจ | เกณฑ์ยอมรับ | ผล |
|---|---|---|---|
| ผู้กู้ (Borrower) | เข้า Dashboard, สร้างคำขอกู้, ดูสัญญา, ส่งหลักฐานชำระเงิน, ส่งออกตารางผ่อน | เห็นเฉพาะข้อมูลที่ได้รับอนุญาตและระบบตรวจข้อมูลก่อนบันทึก | ผ่าน regression/route smoke; ต้องยืนยันกับข้อมูลสัญญาจริง |
| ผู้ให้กู้ (Lender) | ตรวจคำขอกู้, อนุมัติหรือปฏิเสธ, ตรวจยอดและรายการชำระ | การเปลี่ยนสถานะและข้อมูลที่เกี่ยวข้องเป็นไปตามสิทธิ์ | ผ่าน router/mutation regression; ต้องให้ผู้แทนผู้ให้กู้ยืนยัน workflow จริง |
| ผู้ดูแลระบบ (Admin) | Dashboard, Drill-down, Activity History, Audit Logs, Governance, Presets/Folders | RBAC, export gate, audit metadata และ owner-scoped preference ทำงานตาม contract | ผ่าน regression, render contracts และ visual smoke |
| ผู้ใช้ทุกบทบาท | Profile, theme, notification preferences, responsive layout | ไม่เปิดเผยข้อมูลลับ, มี loading/error state และรองรับมือถือ | ผ่าน component/route smoke; ช่องทางภายนอกต้องตั้งค่าจริง |

## UAT Matrix รายฟังก์ชัน

| กลุ่มงาน | เคสที่ยืนยันแล้ว | สถานะ | หมายเหตุสำหรับ UAT ผู้ใช้ |
|---|---|---|---|
| การยืนยันตัวตนและสิทธิ์ | Session/auth contracts, role guards และ access fallback | ผ่าน | ทดสอบด้วยบัญชี Borrower/Lender/Admin ที่ได้รับมอบหมาย |
| คำขอกู้และดอกเบี้ย | Validation, simple/compound calculation และ amortization utility | ผ่าน | เปรียบเทียบยอดกับนโยบายดอกเบี้ยขององค์กรอย่างน้อย 2 กรณี |
| อนุมัติและสัญญา | Mutation contracts สำหรับอนุมัติ/ปฏิเสธและข้อจำกัดสถานะ | ผ่าน | ยืนยันข้อความ/เงื่อนไขอนุมัติกับผู้ให้กู้จริง |
| การชำระเงิน | Validation การชำระ, การตรวจ/ปฏิเสธ และ export utility | ผ่าน | ใช้ไฟล์สลิปจริงที่ไม่ใช่ข้อมูลอ่อนไหวในการทดสอบ |
| การแจ้งเตือน | Preferences, audit และ authorization สำหรับ Email/LINE | ผ่านเชิงโปรแกรม | ต้องตั้งค่า SMTP/LINE provider แล้วส่งทดสอบกับผู้รับที่อนุมัติ |
| Admin Dashboard | KPI, charts, date ranges, drill-down และ lazy export | ผ่าน | ข้อมูลว่างจะแสดง empty state แทนการสร้างตัวเลขจำลอง |
| Audit/Governance | Filter, search, virtual list, export, reference code, approval/retention contracts | ผ่าน | ให้ผู้อนุมัติทดสอบ dual-control ด้วยข้อมูลที่ได้รับอนุญาต |
| Preset และ Folder | Scope, creator filter, pins, DnD, categories, history, Undo/Redo และ CSV metadata | ผ่าน | ทดสอบร่วมกันอย่างน้อย 2 Admin เพื่อยืนยัน owner isolation |
| การนำทาง | `/`, `/dashboard`, `/loan/create`, `/loan/:id`, `/loan/:id/payment`, `/admin`, `/admin/activity-history`, `/admin/audit-logs`, `/admin/report-governance`, `/settings/notifications`, `/profile`, `/404` | ผ่าน visual smoke | หน้ารายการที่อ้างอิง ID จะรอข้อมูลหรือแสดง state ที่เหมาะสมเมื่อไม่มีสัญญาที่เข้าถึงได้ |

## การทดสอบ UAT ที่ผู้ใช้ควรรับรองร่วมกัน

เนื่องจากระบบไม่เพิ่มข้อมูลทดสอบลงฐานข้อมูลจริงโดยอัตโนมัติ การรับรองขั้นสุดท้ายควรทำในสภาพแวดล้อม UAT ที่มีบัญชีทดสอบและข้อมูลที่ผ่านการอนุมัติขององค์กร ผู้แทนแต่ละบทบาทควรลงชื่อรับรองตามรายการด้านล่างหลังปฏิบัติจริงครบถ้วน

| รหัส | ขั้นตอนทดสอบด้วยผู้ใช้จริง | ผลที่คาดหวัง | ผู้รับผิดชอบ |
|---|---|---|---|
| UAT-B01 | Borrower สร้างคำขอกู้แบบดอกเบี้ยคงที่และลดต้นลดดอก | ยอดรวมและตารางผ่อนตรงกับนโยบายธุรกิจ | ตัวแทนผู้กู้ |
| UAT-L01 | Lender อนุมัติหนึ่งคำขอและปฏิเสธหนึ่งคำขอ | สถานะ/สัญญา/สิทธิ์เปลี่ยนอย่างถูกต้อง | ตัวแทนผู้ให้กู้ |
| UAT-P01 | Borrower อัปโหลดสลิป, Lender/Admin ตรวจและยืนยัน | ประวัติการชำระและยอดคงค้างอัปเดตถูกต้อง | ผู้กู้และผู้ตรวจ |
| UAT-N01 | เปิด/ปิด preferences และกระตุ้นเหตุการณ์แจ้งเตือน | ส่งเฉพาะช่องทางที่เปิดใช้งานและผู้รับที่อนุญาต | ผู้ดูแลระบบ |
| UAT-A01 | Admin ใช้ filter/export และ drill-down | ข้อมูล CSV/PDF ตรงกับผลลัพธ์บนจอและอยู่ในสิทธิ์ | ผู้ดูแลระบบ |
| UAT-F01 | Admin สองบัญชีจัด Folder/Preset และย้ายหลายรายการ | หมวดหมู่/ประวัติ/Undo/Redo ของแต่ละบัญชีแยกจากกัน | ผู้ดูแลระบบ 2 คน |

## ข้อสังเกตและความเสี่ยงที่ต้องติดตาม

การ build ผ่านโดยมีคำเตือนเกี่ยวกับ bundle ขนาดเกิน 500 kB ซึ่งเป็นคำเตือนด้านประสิทธิภาพ ไม่ใช่ข้อผิดพลาดในการ deploy และส่วน Chart/PDF ยังถูกแยกโหลดตามเส้นทางเดิม นอกจากนี้ channel การส่ง Email จะไม่ทำงานจนกว่าจะมีการตั้งค่า SMTP และการส่ง LINE ต้องใช้ credential/provider ที่องค์กรอนุมัติ จึงไม่ควรอ้างว่าการแจ้งเตือนภายนอกพร้อมใช้งานก่อนทดสอบ UAT-N01 สำเร็จ

## เกณฑ์การอนุมัติ UAT

ให้ถือว่าระบบผ่าน UAT ขั้นสุดท้ายเมื่อรายการ UAT-B01 ถึง UAT-F01 ไม่มี defect ระดับ Critical/High และผู้แทนธุรกิจรับรองว่าตัวเลข สถานะเอกสาร สิทธิ์ และข้อความที่เกี่ยวข้องตรงกับนโยบายขององค์กร กรณีพบปัญหา ให้บันทึกขั้นตอนทำซ้ำ บทบาทผู้ใช้ วันที่/เวลา และรหัสสัญญาหรือรายการแบบปกปิดข้อมูลส่วนบุคคลเพื่อให้ตรวจสอบได้อย่างปลอดภัย
